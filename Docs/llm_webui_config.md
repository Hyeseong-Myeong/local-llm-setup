# 🌐 Open WebUI 커스텀 설정 가이드 (llm_webui_config.md)

고객님의 하이브리드 워크플로우(Claude + Local Models)를 Open WebUI에서 가장 효율적으로 사용하기 위해 세팅해야 할 항목들을 정리한 가이드입니다. 

기존 터미널(Ollama)에 고정해 두었던 `Modelfile` 방식 대신, **Open WebUI의 GUI 상에서 유연하게 파라미터와 프롬프트를 제어**하는 방법입니다.

---

## 1. 🔌 모델 및 API 연동 (Connections)
Open WebUI의 **관리자 설정(Settings) > 연결(Connections)** 메뉴에서 다음을 확인/설정합니다.

* **Ollama 연동:** 
  * `http://127.0.0.1:11434` 가 정상적으로 등록되어 있는지 확인합니다. 연결되면 앞서 터미널에서 다운로드한 로컬 모델들이 자동으로 UI에 노출됩니다.
* **Claude (Anthropic) API 연동:**
  * 기본 뼈대 설계를 위해 Claude API를 WebUI 안에서 직접 호출하려면, **Settings > Connections > OpenAI API** 란(또는 최신 버전의 Anthropic 전용란)에 Anthropic API Key를 입력하여 클라우드 모델도 Open WebUI 안에서 통합하여 사용하세요.

---

## 2. 🎛️ 전역 파라미터 튜닝 (Advanced Parameters)
코딩과 리팩토링의 퀄리티를 좌우하는 핵심 파라미터를 설정합니다. (채팅창 우측 상단의 🎛️ 제어 아이콘 또는 모델 설정에서 수정 가능)

| 파라미터 | 권장값 | 설명 |
| :--- | :---: | :--- |
| **Temperature (온도)** | `0.1 ~ 0.2` | 코딩, 논리 디버깅 시에는 창의성보다 **정확성과 일관성**이 중요합니다. 기본값(0.8)을 0.1~0.2 수준으로 대폭 낮추세요. |
| **Context Length (문맥 길이)** | `16384` 이상 | 리팩토링 시 코드를 복사+붙여넣기 할 때 잘리지 않도록 컨텍스트(num_ctx)를 넉넉하게 잡아줍니다. |
| **Top P / Top K** | `0.9` / `40` | 코딩용 모델의 스탠다드 세팅입니다. (온도를 낮추면 기본적으로 제어됩니다.) |

## 4. 💡 Open WebUI 사용 꿀팁 (Workflow 연계)

* **문서 첨부 (RAG):**
  EXAONE 기반 모델과 대화할 때, Open WebUI의 `+` 버튼을 눌러 PDF나 마크다운 파일을 던져주면 빠르고 정확한 한국어 문서 요약 및 추출이 가능합니다.

## 5. 🌐 심층 웹 검색 (Agentic Web Search) 세팅 가이드

Open WebUI의 기본 웹 검색 기능은 단순히 '키워드 검색 후 상위 N개 페이지의 텍스트 일부(Chunk)만 가져와서 요약'하는 기초적인 RAG 방식입니다. 이를 극복하기 위한 심화 설정입니다.

### 1단계: AI 전용 검색 엔진(Tavily) 도입
일반 검색 엔진(DuckDuckGo 등) 대신, LLM 전용으로 개발된 리서치 검색 엔진을 연결합니다.
* **추천:** [Tavily](https://tavily.com/) (무료 API 제공)
* **설정 방법:** Open WebUI의 **설정(Settings) > 웹 검색(Web Search)** 메뉴에서 엔진을 `Tavily`로 변경하고 API Key를 입력합니다. 

### 2단계: Tools(함수 호출) 기능을 통한 원문 전체 탐색
모델이 단순히 검색 결과 목록만 보는 것이 아니라, **"이 링크는 원문 전체를 자세히 읽어봐야겠다"**고 스스로 판단하여 웹페이지를 통째로 긁어오게 만듭니다.

* **💡 질문 1. Tavily(1단계)와 Tools(2단계)를 동시에 쓸 수 있나요?**
  * **네, 완벽하게 시너지가 납니다!** 
  * 사용자가 질문하면 ➡️ 1차로 **Tavily**가 검색을 수행해 관련 URL 목록과 요약을 모델에게 줍니다. ➡️ 모델이 요약을 읽고 "더 깊은 정보가 필요하다"고 판단하면 ➡️ 2차로 **Tool (웹 스크래퍼)**을 스스로 호출하여 Tavily가 찾아준 URL에 직접 접속해 전체 본문을 정독합니다.

* **💡 질문 2. Open WebUI Hub에서 어떤 툴을 추천하나요? (크롤러/스크래퍼 추천 TOP 6)**
  Open WebUI Hub(https://openwebui.com/)에서 다음 툴들을 확인해 보세요. (다운로드 수는 Hub 기준 대략적인 수치입니다.)

  1. **[Enhanced Web Scrape](https://openwebui.com/posts/enhanced_web_scrape_c023613c)** *(누적 다운로드: 20,470+)* **[🔥 가장 강력히 추천]**
     * **설명 및 비교:** 고객님께서 찾아주신 바로 그 툴입니다! 기존 'Jina Reader'의 핵심 기능(`r.jina.ai` 마크다운 변환)을 베이스로 하되, **WebUI 채팅창에 현재 진행 상황("Scraping...", "Cleaning up...")을 띄워주는 Emitter 기능**과 불필요한 링크를 제거해 토큰을 아껴주는 기능이 추가된 **완벽한 상위 호환 버전**입니다. 무조건 이 툴을 쓰시는 것을 추천합니다.
  2. **[Jina Reader (Original)](https://openwebui.com/search?q=jina+reader)** *(누적 다운로드: 약 50,000+)*
     * **설명:** 가장 기본적이고 널리 쓰이는 Jina 전용 툴입니다. 군더더기 없이 마크다운 변환만 수행합니다. (현재는 위 1번 Enhanced 버전을 쓰는 것이 UI 피드백 면에서 훨씬 훌륭합니다.)
  3. **[BeautifulSoup URL Reader](https://openwebui.com/search?q=beautifulsoup)** *(누적 다운로드: 약 30,000+)*
     * **설명:** 가장 가벼운 파이썬 기반 크롤러입니다. 위키피디아 같은 단순 텍스트 사이트를 읽을 때 속도가 가장 빠르지만 자바스크립트 렌더링은 불가능합니다.
  4. **[Firecrawl](https://openwebui.com/search?q=firecrawl)** *(누적 다운로드: 약 15,000+)*
     * **설명:** 하위 페이지(Sub-pages)까지 통째로 타고 들어가는 깊은 크롤링이 필요할 때 강점이 있는 최신 LLM 전용 스크래퍼입니다.
  5. **[Playwright Web Scraper](https://openwebui.com/search?q=playwright)** *(누적 다운로드: 약 10,000+)*
     * **설명:** 자바스크립트(SPA) 렌더링이 필수적인 동적 웹사이트(뉴스, 쇼핑몰 등)의 본문을 실제 브라우저처럼 렌더링해서 긁어옵니다.
  6. **[Browserless API](https://openwebui.com/search?q=browserless)** *(누적 다운로드: 약 5,000+)*
     * **설명:** 캡챠(CAPTCHA) 등 안티봇(Anti-Bot) 방어막이 쳐져 있는 깐깐한 사이트들을 우회하여 접속하는 데 특화된 툴입니다.

### 3단계: Pipelines를 활용한 딥 리서치(Deep Research)
단순한 1회성 검색이 아니라, **"검색 -> 결과 분석 -> 정보 부족 시 재검색 -> 종합"** 이라는 다단계 리서치 에이전트를 구현합니다.

* **💡 질문 3. 모델 선택창에 Pipeline이 안 보입니다. 어떻게 하나요?**
  * Pipeline은 Open WebUI 자체 기능이 아니라, **별도의 백그라운드 파이썬 서버**를 하나 더 띄워야 연동되는 확장 기능입니다. 다음 순서로 연동해야 모델 선택창에 나타납니다.
  1. **파이프라인 서버 구동:** 터미널을 열고 Open WebUI Pipelines 저장소(https://github.com/open-webui/pipelines)를 클론한 뒤, `sh start.sh` (또는 docker)로 별도의 서버(보통 9099 포트)를 실행합니다.
  2. **에이전트 스크립트 설치:** 파이프라인 서버 폴더 안에 커뮤니티에서 다운로드한 `deep_research_pipeline.py` 같은 에이전트 스크립트를 넣습니다.
  3. **WebUI에 연결:** Open WebUI의 **관리자 설정(Settings) > 연결(Connections)**로 들어가서, `OpenAI API` 추가 섹션에 파이프라인 서버 주소(`http://127.0.0.1:9099`)와 API Key(`0p3n-w3bu!`)를 등록합니다.
  4. **완료:** 설정이 정상적으로 연결되면, 모델 선택 창에 `gpt-oss-20b` 같은 일반 모델 옆에 톱니바퀴 아이콘이 붙은 **`Deep Research Pipeline`** 이라는 가상의 모델이 새롭게 등장합니다. 이 모델을 선택하고 질문하면 에이전트가 작동합니다.

### ⚙️ [부록] 관리자 설정: 웹 검색 및 문서 기본 설정 가이드
Open WebUI의 **설정(Settings) > 문서(Documents) / 웹 검색(Web Search)** 메뉴에 있는 세부 설정값들에 대한 권장 가이드입니다.

| 설정 항목 | 권장값 | 설명 |
| :--- | :---: | :--- |
| **임베딩 검색 우회 (Bypass Embedding Search)** | `Off (비활성화)` | 켜게 되면 로컬 ChromaDB를 이용한 문서 검색(RAG)이 무시됩니다. 로컬 위키 문서 첨부 기능을 쓰려면 반드시 꺼두어야 합니다. |
| **청크 크기 / 겹침 (Chunk Size / Overlap)** | `1000` / `250` | (추가 권장) 이력서/PDF 업로드 시 한국어 문장이 중간에 잘려 RAG 품질이 떨어지는 것을 막아줍니다. |
| **웹 콘텐츠 불러오기 생략 (Skip Web Content Fetching)** | `Off (비활성화)` | 켜게 되면 검색 엔진이 주는 1~2줄짜리 짧은 스니펫(미리보기)만 읽고 맙니다. 원문을 딥리딩하게 하려면 반드시 끄세요. |
| **신뢰 할 수 있는 프록시 환경 (Trusted Proxy Environment)** | `Off (비활성화)` | 개인 로컬 PC 환경이므로, 외부 프록시 서버(Nginx 등) 우회 설정이 필요하지 않습니다. |
| **로더 / 웹 로더 엔진 (Web Loader Engine)** | `Playwright` 또는 `BeautifulSoup` | 자바스크립트 웹사이트를 자주 읽힌다면 `Playwright`를, 가볍고 빠른 스크래핑 위주라면 `BeautifulSoup`을 선택하세요. |
| **Timeout (요청 대기 시간)** | `15000` (15초) | 사이트가 응답하지 않을 때 채팅이 영원히 멈추는 것을 방지하기 위해 10~15초 사이로 제한하는 것이 좋습니다. |
| **SSL 인증서 확인 (Verify SSL Certificate)** | `On (활성화)` | 보안을 위해 켜두는 것이 기본입니다. (단, 자체 인증서를 쓰는 사내 로컬 사이트를 긁어와야 한다면 끄세요.) |
| **동시 요청 수 (Concurrent Requests)** | `3 ~ 5` | 검색 결과를 한 번에 몇 개씩 접속해 읽을지 결정합니다. 너무 높으면 사이트에서 IP 차단을 당하거나 로컬 메모리가 터질 수 있습니다. |

## 6. 🚀 추가 권장 설정 가이드 (심화 세팅)

기본 설정 외에 Open WebUI의 활용도를 200% 끌어올려 줄 3가지 필수 심화 설정 방법입니다.

### 1. 전역 시스템 프롬프트 (Global System Prompt) 설정
* **위치:** 설정(Settings) > 일반(General) > 시스템 프롬프트(System Prompt)
* **설명:** 챗봇들이 대화를 시작할 때 기본적으로 깔고 들어가는 **'절대 규칙'**을 정합니다. 개별 모델(Phi-4, EXAONE 등)의 성향과 무관하게, 고객님의 서버에서 구동되는 모든 AI가 공통적으로 지켜야 할 뼈대 가이드라인을 주입할 수 있습니다.
* **권장 프롬프트 예시:**
  > "너는 언제나 한국어로 대답해야 한다. 불필요한 인사말이나 서론은 생략하고, 질문에 대한 핵심만 바로 말해라. 코드를 작성할 때는 반드시 Markdown 코드 블록을 사용하고, 코드 내 주석은 한국어로 작성해라."

### 2. 음성 대화 기능 활성화 (TTS / STT API 연동)
* **위치:** 설정(Settings) > 오디오(Audio)
* **설명:** 화면 우측 하단의 마이크/스피커 버튼을 눌러, 실제 비서와 대화하듯 **음성으로 소통(Call 기능)**하게 해주는 강력한 세팅입니다.
* **설정 가이드:**
  * **STT (음성 인식):** 고객님의 목소리를 텍스트로 바꿉니다. 기본 내장 엔진(WebAPI)을 쓰거나, 더 높은 정확도를 원하시면 `OpenAI (Whisper)` 엔진을 선택하세요.
  * **TTS (음성 출력):** AI의 텍스트 답변을 목소리로 읽어줍니다. `OpenAI API` 호환 엔진을 선택하고, ElevenLabs 같은 고품질 음성 전문 API 키를 연동해두면 실제 사람과 구분이 가지 않는 아주 자연스러운 한국어 비서가 완성됩니다.

### 3. 채팅방 컨텍스트 메모리 제한 (num_ctx) 튜닝
* **위치:** 채팅방 우측 상단 🎛️ 제어판 아이콘 > 고급 파라미터(Advanced Parameters) > `num_ctx` (Context Length)
* **설명:** 대화가 길어지고 웹 검색을 많이 할수록, 모델이 기억해야 할 과거 대화(Context)가 쌓여 VRAM(8GB)을 급격히 갉아먹습니다. 이 한도를 적절히 제어해야 컴퓨터가 뻗는 현상(OOM)을 막을 수 있습니다.
* **상황별 권장 설정값:**
  * **일상적인 핑퐁 대화 및 코딩 헬퍼:** `4096` 또는 `8192` (메모리를 아끼고 속도를 높임)
  * **거대 코드베이스 통째로 리팩토링 / 웹 검색(RAG) 심층 분석:** `16384` 이상 (일시적으로 늘려서 전체 문맥을 파악하게 하되, 작업이 끝나면 다시 줄이는 것을 권장합니다.)
