# 🤖 로컬 모델 심층 비교 분석 및 추천 가이드 (model_compair.md)

고객님의 하드웨어(**Ryzen 5600X, 32GB RAM, 8GB VRAM RX 6600 XT**) 환경을 기준으로, 요청하신 각 모델 가문(Family)별 **최적의 구동 가능 모델**을 선정하고 상세 비교 분석을 제공합니다.

> **💡 하드웨어 분석 노트**
> 8GB VRAM에는 약 7~8B 체급의 모델을 온전히 올려 매우 빠르게 구동할 수 있으며, 32GB RAM을 활용하면 12B~32B 체급의 강력한 모델을 GPU와 CPU에 나누어(Offloading) 구동할 수 있습니다. (MoE 모델의 경우 더 큰 체급도 빠르게 구동 가능합니다.)

---

## 1. DeepSeek-R1 가문
* **추천 모델:** **`DeepSeek-R1-Distill-Qwen-14B`** (최대 지능을 원한다면 32B)
* **특징:** 스스로 질문하고 고민(Chain-of-Thought)한 뒤에 답변을 내놓는 차세대 '추론 전문' 모델입니다.
* **하드웨어 적합성 (14B 기준):** 32GB RAM 시스템에 여유롭게 안착하며, 8GB VRAM에 상당 부분 오프로딩되어 속도와 지능의 밸런스가 가장 좋습니다.
* **장점:** 복잡한 아키텍처 설계, 난해한 버그 추적, 리팩토링에서 압도적인 심층 사고 능력을 보여줍니다.
* **단점:** 답변을 내놓기 전 `<think>` 과정이 길어 단순한 질문에는 오히려 답답할 수 있습니다.
* **예상 구동 속도:** 14B 기준 초당 15~20토큰 내외 (32B는 초당 5~8토큰)
* **커뮤니티 후기:** "작은 모델로도 어설픈 70B 모델보다 똑똑하게 코드를 짠다", "리팩토링 시 놓치기 쉬운 엣지 케이스를 스스로 생각해서 막아준다"며 극찬을 받습니다.

---

## 2. Phi-4 가문 (Microsoft)
* **추천 모델:** **`Phi-4 (14B)`**
* **특징:** 인터넷의 쓰레기 데이터 대신 '고품질 교과서 및 논문 데이터'를 집중 학습시켜 크기 대비 밀도 높은 지식을 자랑합니다.
* **하드웨어 적합성:** 14B 단일 사이즈로 고객님의 시스템(GPU+RAM 하이브리드)에 완벽하게 맞습니다.
* **장점:** 수학적 논리 전개와 알고리즘 문제 해결 능력이 탁월합니다. 파이썬이나 C++ 등 로직 중심 코딩에 강합니다.
* **단점:** 14B 특성상 한국어 등 비영어권 언어 생성 시 가끔 어색한 직역투가 발생할 수 있습니다.
* **예상 구동 속도:** 초당 15~20토큰 내외
* **커뮤니티 후기:** "크기가 믿기지 않는 코딩 로직 몬스터", "MS가 만든 만큼 코딩과 논리에서는 동체급 최강"이라는 평이 지배적입니다.

---

## 3. Ministral 가문 (Mistral AI)
* **추천 모델:** **`Ministral 3 (8B / 14B)`** (최신 3세대 라인업 적용)
* **특징:** 기존 Mistral-Nemo(12B)를 대체하는 Mistral AI의 최신(2025/2026) 경량화 모델 라인업입니다.
* **하드웨어 적합성:** 8B 모델은 8GB VRAM에 100% 쾌적하게 들어가며, 14B 모델은 32GB RAM과 혼합하여 구동 가능합니다.
* **장점:** 엄청나게 긴 컨텍스트 윈도우를 안정적으로 처리하여, 방대한 프로젝트 파일들을 통째로 프롬프트에 넣고 리팩토링할 때 매우 강력합니다.
* **단점:** DeepSeek-R1과 같은 깊은 자가 추론 과정은 없으므로, 아주 생소하거나 극도로 복잡한 '새로운 알고리즘 창조'에는 한계가 있습니다.
* **예상 구동 속도:** 8B 기준 초당 40~50 토큰 / 14B 기준 초당 15~20 토큰
* **커뮤니티 후기:** "과거 Nemo 12B 시절보다 한층 더 날카로워진 코딩 실력", "8B와 14B 선택지가 생겨 하드웨어에 맞추기 좋다"

---

## 4. Gemma 4 가문 (Google DeepMind)
* **추천 모델:** **`Gemma 4 12B`** (또는 `Gemma 4 26B MoE`)
* **특징:** 구글의 최신 오픈웨이트 모델로, 멀티모달 기능과 강력한 추론 능력을 통합한 구조입니다. 
* **하드웨어 적합성:** 12B는 빠르고 쾌적하며, **26B MoE(전문가 혼합)** 모델의 경우 전체 크기는 크지만 한 번에 활성화되는 파라미터가 적어 32GB RAM 환경에서 고성능으로 매끄럽게 돌아갑니다.
* **장점:** 에이전트 워크플로우에 특화되어 있으며, 외부 도구(Tool calling) 사용 능력이 아주 뛰어납니다.
* **단점:** 구글 특유의 강력한 안전 필터(Safety Guardrails) 때문에 간혹 무해한 요청도 검열하는 경우가 있습니다.
* **예상 구동 속도:** 12B 기준 초당 25 토큰 내외 / 26B MoE 기준 초당 10~15 토큰
* **커뮤니티 후기:** "Gemma 4 MoE 모델은 로컬 램이 허락하는 한 최고의 가성비 모델", "에이전트 구현용으로는 오픈소스 중 가장 정교하게 동작한다"

---

## 5. EXAONE (엑사원 - LG AI Research)
* **추천 모델:** **`EXAONE 3.5 7.8B Instruct`** (최신 버전 3.5 적용)
* **특징:** LG AI 연구원에서 2024년 말에 공개한 최신 오픈소스 모델(EXAONE 3.5)로, 한국어와 영어를 동시에 완벽하게 이해하도록 설계된 이중 언어(Bilingual) 특화 모델입니다.
* **하드웨어 적합성:** 7.8B 크기로 고객님의 **8GB VRAM에 100% 안착**하여 CPU와 RAM 소모 없이 빛의 속도로 동작합니다.
* **장점:** 한국어 어휘력과 자연스러움 면에서는 동급 8B 체급 중 압도적 원탑입니다. 긴 한국어 문서를 요약하거나 RAG(검색 증강 생성)에 특화되어 환각이 적습니다.
* **단점:** 글로벌 빅테크의 대형 모델 대비 코딩 능력이나 복잡한 아키텍처 추론 능력은 상대적으로 떨어질 수 있습니다. (코딩은 Phi-4나 DeepSeek 권장)
* **예상 구동 속도:** 초당 40~50+ 토큰 (가장 빠름)
* **커뮤니티 후기:** "한국어 자연스러움은 3.5버전에 와서 더욱 완벽해졌다", "로컬 VRAM 8GB 환경에서 한국어 메인 비서로 이만한 게 없다"

## 6. KIMI (Moonshot AI)
* **추천 모델:** ⚠️ **구동 불가 (하드웨어 제약)**
* **특징:** 중국의 Moonshot AI에서 오픈소스로 공개한 K2 시리즈(K2.6, K2.7 Code)는 에이전트 코딩 작업에 특화되어 있습니다.
* **하드웨어 적합성 (불가):** Kimi의 오픈소스 모델들은 대부분 전체 **1조 개(1 Trillion)**의 파라미터(활성화 32B)를 가지는 거대한 MoE 모델입니다. **고객님의 32GB RAM 및 8GB VRAM으로는 가중치(Weights)를 로드하는 것조차 불가능**합니다. (수백 GB의 VRAM/RAM을 요구하는 서버급 모델입니다.)
* **대안:** Kimi 모델은 로컬 구동 대신 Moonshot AI의 API를 활용하는 것을 권장합니다.

## 7. GPT-OSS (OpenAI 오픈웨이트)
* **추천 모델:** **`GPT-OSS-20B`**
* **특징:** OpenAI가 공개한 소형 고효율 MoE 모델로, 자체적인 로컬 에이전트 시스템에 최적화되어 있습니다.
* **하드웨어 적합성:** 전체 파라미터는 21B이지만 추론 시 3.6B만 활성화하므로, 고객님의 **8GB VRAM과 32GB RAM 환경에서 극도의 쾌적함과 똑똑함**을 동시에 누릴 수 있습니다.
* **장점:** OpenAI 특유의 체인 오브 소트(Chain-of-Thought) 논리 전개 능력을 로컬에서 사용할 수 있으며, 도구 호출(Function calling)의 안정성이 매우 뛰어납니다.
* **단점:** 특정 Harmony 프롬프트 포맷을 엄격하게 지켜야 최고의 성능이 나오므로 설정이 다소 까다로울 수 있습니다.
* **예상 구동 속도:** 초당 25~30 토큰 (MoE 특성상 활성화 파라미터가 적어 체급 대비 매우 빠름)
* **커뮤니티 후기:** "OpenAI의 감성을 로컬에서 느낄 수 있는 최고의 타협 모델", "코딩과 일반 대화 모두 부드럽고 똑똑하다"

## 🔍 심층 비교: 코딩 보조용 Phi-4 (14B) vs GPT-OSS-20B

코딩 보조 및 일상적인 챗봇 역할을 수행할 모델로 두 모델을 고민 중이시라면, 다음의 세부 비교를 참고해 보세요.

| 비교 항목 | Phi-4 (14B) | GPT-OSS-20B (MoE) |
| :--- | :--- | :--- |
| **아키텍처** | **Dense (밀집형):** 140억 개의 파라미터를 매번 모두 사용하여 답변을 생성합니다. | **MoE (전문가 혼합):** 총 210억 개 중, 상황에 맞는 **36억 개**의 파라미터만 활성화하여 답변합니다. |
| **메모리(RAM) 효율** | 14B 전체가 로드되어야 하므로 VRAM(8GB)을 넘쳐 시스템 RAM을 일부 사용합니다. | 가중치 로드 자체는 RAM을 많이 쓰지만, **추론(생성) 시에는 활성화 파라미터가 적어 체감 속도가 훨씬 빠릅니다.** |
| **성향 & 강점** | **"엄격한 학자"**<br>마이크로소프트의 고품질 교과서/논문 데이터로 학습되어 **알고리즘, 수학, 논리적 버그 추적**에 변태적인 성능을 보입니다. | **"유능한 실무자"**<br>ChatGPT처럼 부드럽고 융통성 있게 대화하며, 외부 툴(Function calling) 연동 등 **에이전트 시스템(OpenWebUI 등)과의 호환성**이 압도적입니다. |
| **단점** | 지식의 깊이는 깊으나, 대화형(Chat) 특유의 유연함이 부족해 가끔 딱딱하게 답변합니다. | MoE 특성상 아주 깊고 복잡한 단일 논리(수학 증명 등)에서는 Phi-4보다 논리력이 살짝 떨어질 수 있습니다. |
| **추천 대상** | 꼬여있는 스파게티 코드의 **로직을 뚫어지게 분석하고 정교한 알고리즘을 짤 때** | IDE에 연동하여 **자동완성을 쓰거나, 핑퐁 대화하며 코드 뼈대(Boilerplate)를 빠르게 만들 때** |

## 💻 Ollama 모델 관리 (다운로드 및 삭제 명령어)

기존에 테스트용으로 설치하셨던 모델(예: `qwen-master` 등)을 삭제하고, 새로 결정하신 모델들을 다운로드하는 명령어입니다. 명령 프롬프트(CMD)나 파워쉘에서 아래 명령어들을 실행하시면 됩니다.

### 🗑️ 1. 기존 모델 삭제 (안 쓰는 모델 지우기)
```bash
# qwen-master 커스텀 모델 삭제
ollama rm qwen-master

# (만약 이전 버전의 qwen 등 안쓰는 모델이 있다면 동일하게 삭제)
# ollama rm [모델명]
```

### 📥 2. 신규 추천 모델 다운로드
```bash
# 1. 메인 챗봇 및 보조 모델 (이미 있으신 경우 건너뛰셔도 됩니다)
ollama pull qwen3.5:9b

# 2. 코딩 리팩토링 및 심층 추론용 (현재 설치되어 계신 것으로 보입니다!)
ollama pull deepseek-r1:14b

# 3. 한국어 특화 문서/요약용 (엑사원)
ollama pull exaone3.5:7.8b
# (참고: Ollama 공식 라이브러리 명칭에 따라 exaone3.5 혹은 hf.co/LGAI-EXAONE/EXAONE-3.0-7.8B-Instruct-GGUF 등 허깅페이스 GGUF 다이렉트 주소를 사용해야 할 수 있습니다.)

# 4. 코딩 보조 및 로직 디버깅용 (최종 확정)
ollama pull phi4
```

> **💡 확인 팁:** 
> 설치된 전체 모델 리스트를 보려면 `ollama list` 명령어를 입력하세요!
