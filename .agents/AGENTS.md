# Agent Rules

- **사전 동의 원칙:** 기존에 합의된 설정(버전, IP 바인딩, 아키텍처 등)을 기술적 이유로 수정하거나, **설정 변경 후 시스템(컨테이너 등)을 재시작/실행할 때에는 무조건 어떤 변화(코드/설정)가 있었는지 먼저 사용자에게 상세히 설명하고, 명시적인 동의(실행 승인)를 구한 뒤에만 실행 명령을 내릴 것.** (어떤 경우에도 사용자 몰래 백그라운드 재시작 명령어 임의 실행 금지)
- **문서 기반 작업 원칙:** 단편적인 대화 맥락만으로 임의 판단하여 작업하지 말 것. 항상 기획 문서(`LLM_system_extend_loadmap.md`)와 `task.md`를 전체적으로 꼼꼼히 확인하고, 작업 전 누락된 부분이나 향후 재시작이 필요한 병목 지점을 미리 파악하여 한 번에 구성할 것. 의문이 생기면 임의 진행하지 말고 반드시 사용자에게 먼저 확인할 것.
- **사용자 개입 대기 원칙:** 사용자가 직접 수행해야 하는 작업(예: `.env` 파일 수정, 시스템 설정 등)이 필요한 경우, 다음 단계로 넘어가지 말고 작업 내역을 명시적으로 안내한 뒤 사용자의 '완료' 응답이 올 때까지 대기할 것.
- **환경변수 원칙 및 .env 접근 금지:** 모든 시크릿 키, 인증 정보, Base URL 등은 하드코딩을 금지합니다. 단, 에이전트는 사용자의 실제 `.env` 파일에 절대 접근(Read/Write)해서는 안 됩니다. 새로운 환경변수가 필요하면 반드시 `.env.example`에 키(Key)만 추가(`KEY=""`)하고, 실제 값 입력은 사용자에게 안내하여 사용자가 직접 `.env`에 입력하도록 합니다.
- **Git 커밋/푸시 원칙:** 명시적인 사용자 지시가 없이는 절대로 커밋(commit), 푸시(push), 혹은 PR(Pull Request) 명령어를 단독으로 실행하지 마십시오. 코드는 항상 상태 추적을 유지하되 동의 없이는 스냅샷을 생성하지 마십시오.
- **디버깅 및 트러블슈팅 원칙:** 에러가 발생했을 때 맹목적인 재실행(Trial-and-Error)이나 터미널 명령어를 남발하지 마십시오. 반드시 가장 먼저 로그 파일을 확인하여 근본 원인을 파악하고, 증상만 회피하는 땜질식 처방(Band-aid Fix) 대신 코드 상의 근본적인 수정을 진행하십시오.
- **Windows 인코딩 대응 원칙:** 백그라운드 환경(`pythonw.exe` 등)에서 시스템을 실행할 때, 콘솔 출력이 없거나 `CP949` 기본 인코딩 문제로 크래시가 발생할 수 있습니다. 이를 방지하기 위해 로거(예: `logger_setup.py`)를 프로그램 최상단에서 먼저 로드하여 표준 입출력을 `UTF-8` 파일로 리다이렉트하는 방식을 적용하십시오. 텍스트 내 이모지 제거 등은 근본 해결책이 아닙니다.
- **아티팩트 및 임시 파일 정리:** `crash_log.txt`와 같은 임시 테스트 결과나 로그 파일을 작업 디렉토리 최상단에 방치하지 마십시오. 테스트가 끝나면 즉시 삭제하거나 `logs` 폴더 등 지정된 경로로 이동하십시오.
